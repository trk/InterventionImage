# Runtime Health Verification and Priority Fallback for Vips Driver

`InterventionImage` supports `libvips` via `intervention/image-driver-vips` (`jcupitt/vips`), which relies on PHP's `FFI` extension. Because many PHP environments default to `ffi.enable=preload` (allowing FFI in CLI workers such as `wire image:queue` while restricting it in web SAPIs unless `ffi.enable=1` is configured), checking `extension_loaded('ffi')` alone is insufficient and would cause fatal runtime errors on HTTP requests. We therefore verify driver readiness by invoking `DriverInterface::checkHealth()` inside a guarded `try/catch` block during initialization, ordering `auto` detection as `vips -> imagick -> gd` and falling back to the next healthy driver when the preferred driver is unavailable in the active SAPI.
